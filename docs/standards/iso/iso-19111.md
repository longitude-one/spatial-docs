---
title: ISO 19111 — Referencing by coordinates
description: Assesses coordinate reference concepts, implementation limitations and the unresolved LongitudeOne reference edition.
---

ISO 19111 describes coordinate reference systems and coordinate operations.
LongitudeOne stores reference identifiers alongside coordinates; that capability
does not implement the complete CRS model or establish ISO conformance.

## Normative source

- ISO, **ISO 19111:2007**, *Geographic information — Spatial referencing by
  coordinates*, edition 2, July 2007: [ISO catalogue][iso2007].
- ISO, **ISO 19111:2019**, *Geographic information — Referencing by coordinates*,
  edition 3, January 2019: [ISO catalogue][iso2019].
- Verified technical source: OGC **08-015r2**, *The OGC Abstract Specification,
  Topic 2: Spatial referencing by coordinates*, version **4.0.0**,
  **2010-04-27**: [official PDF][ogc2007]. Its preface states consistency with
  ISO 19111:2007. Citations below refer to this OGC document, rather than claiming
  a direct inspection of the ISO publication.

Amendments and corrigenda have not been assessed. ISO 19111:2019 requirements
have not been assessed here. The ISO catalogue identifies editions; it does not
provide evidence for the technical clauses summarized below.

## Purpose and scope

The relevant subjects are the definition of a CRS, its axes and units,
identification of reference objects, and operations that change coordinates.
These distinguish an identifier attached to a geometry from a complete reference
system definition and from a calculation that changes its coordinates.

This assessment covers the 2007 model through OGC 08-015r2. It does not assess
the later dynamic-reference model, CRS encodings or DBMS axis conventions.

## Relevant requirements

**Normative summaries from OGC 08-015r2:**

- **CRS definition (8.2.1):** a CRS combines a coordinate system and a datum;
  the datum connects the coordinate system to the referenced object.
- **Axes and tuples (9.2):** the coordinate system defines axis names, units,
  directions and sequence. A coordinate tuple has one ordinate per axis and
  follows that axis sequence.
- **Identification (7.2, Tables 1–2):** an object identifier can refer to defining
  information held elsewhere. An identifier is distinct from that information.
- **Operations (11.1):** a conversion changes coordinates between CRSs sharing
  a datum; a transformation changes coordinates between different datums.

**Informative explanation:** recording `EPSG:4326` supplies a reference to a
definition. It does not itself provide axes, units, datum parameters or a
coordinate operation implementation. A PHP XY/XYZ/XYM/XYZM layout alone cannot
establish conformity with the axes of a particular CRS.

## LongitudeOne support

**Assessed implementation:** Spatial Types pre-1.0 development snapshot after
`0.0.1-alpha.4`, revision `ceaee5d142c77fc3922ab50c762fa6648fea0e30`.
This is evidence about a development snapshot, not a released 1.x promise.
No DBMS integration is assessed.

| Feature | Implementation scope | Status | Limitations | Implementation decision | Extensions | Evidence |
| --- | --- | --- | --- | --- | --- | --- |
| Reference identification | Types snapshot | Partially supported | Identifier only; no full CRS definition | Integer and optional authority | None documented | [Reference value][reference] |
| CRS definition | Types snapshot | Unsupported | No datum, axes or units model | Reference identity only | None documented | [Reference value][reference] |
| CRS axis validation | Types snapshot | Unsupported | No CRS lookup or tuple/axis verification | Stored ordinates retained | None documented | [SRS guide][guide] |
| Coordinate operations | Types snapshot | Unsupported | External calculation required | Relabeling preserves coordinates | None documented | [SRS guide][guide] |

**LongitudeOne implementation decisions:** `SpatialReference` compares the integer
identifier and optional authority. Identifier `0` is an unnamed reference rather
than a wildcard. Aggregate members must share the parent's full reference.
These identity rules are project behavior, not requirements established by the
ISO 19111 source examined here.

`withSpatialReference()` changes the declared reference on an immutable copy
without calculating new ordinates. It therefore does not perform either of the
coordinate operations described in OGC 08-015r2, clause 11.1. A caller must obtain
the target ordinates through an external component.

**Extensions:** none are documented for this assessed subset. This is not an
ecosystem-wide absence claim. No blanket ISO 19111 conformance is claimed.
